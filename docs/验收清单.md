# 验收清单

## 资格

- [ ] 能以公众号/服务号运营者身份完成微信授权。
- [ ] 接受随机长路径下的只读 RSS 公网访问。

## 容器与配置

- [ ] `docker compose config --quiet` 通过。
- [ ] `docker compose ps` 显示 WeRSS healthy、Caddy running。
- [ ] `docker compose exec -T we-mp-rss uname -m` 返回 `aarch64`。
- [ ] 重启后 SQLite、用户、公众号和文章数据仍在。
- [ ] Docker 日志限制为 10 MB × 3。

## 安全

- [ ] `127.0.0.1:8001` 管理后台正常。
- [ ] 公网 `/` 返回 `404`。
- [ ] 公网 `/api/docs` 返回 `404`。
- [ ] 公网 `/<FEED_PREFIX>/api/docs` 返回 `404`。
- [ ] 公网 `POST /<FEED_PREFIX>/feed/all.atom` 返回 `404`。
- [ ] 公网 `GET /<FEED_PREFIX>/feed/all.atom` 返回 `200`。
- [ ] `curl --path-as-is` 的 dot-segment 请求返回 `404`。
- [ ] 不把 `docker compose logs` 保存到公开 evidence。

自动入口：

```bash
./scripts/verify.sh --local
./scripts/verify.sh --public
```

## 微信抓取

- [ ] 3 个试验公众号都能获得标题、发布时间、正文和图片。
- [ ] 定时任务为 `17 */2 * * *`，保存后已点击“应用”。
- [ ] 至少完成 36 个两小时周期。
- [ ] 聚合源和单公众号源都是合法 XML。

## Folo

- [ ] 聚合源与一个单源已加入“微信公众号测试”。
- [ ] 72 小时内无需重新订阅即可出现新文章。
- [ ] 7 天内至少一篇新文章自动出现。
- [ ] 从 WeRSS 入库到 Folo 出现不超过 12 小时。
- [ ] 若 RSS 已更新但 Folo 未更新，明确归类为 Folo 刷新问题。

## Obsidian

- [ ] 目标目录为 `02_Archive/02_DailyProcessed/reading/folo_inbox`。
- [ ] Base 只显示该目录内带 `folo` 标签的 Markdown。
- [ ] 普通长文、多图文、表格/代码、复杂排版、同标题文章五类样本均已检查。
- [ ] 标题、公众号、时间、原文链接正确，中文无乱码。
- [ ] 已有批注的文件不会被再次保存覆盖。
- [ ] 同名冲突时先改为“发布日期-标题”再重试。
- [ ] 每月同名冲突超过 3 次时，再立项开发 URL 哈希命名桥接。

## 备份与回滚

- [ ] `./scripts/backup.sh` 成功，归档权限为 `600`。
- [ ] 归档包含 `.env`、SQLite、授权文件和稳定密钥。
- [ ] `./scripts/restore-test.sh` 的 SQLite 与独立容器检查通过。
- [ ] 旧镜像摘要可重新启动。

## 当前无法自动完成的门禁

- Docker 协议接受和管理员授权。
- 微信扫码并选择运营账号。
- Tailscale 首次 Funnel 网页批准。
- Folo 登录、Basic 试用/订阅和 Obsidian 集成授权。
- 72 小时与 7 天的时间性观察。
